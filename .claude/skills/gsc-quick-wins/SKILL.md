# GSC: quick wins і аналітика

Вхід: вивантаження GSC (CSV) у `clients/<проєкт>/inbox/`. Найкращий вхід - зріз URL+Query (з API або Looker Studio); UI-експорти однієї розмірності (лише Запити або лише Сторінки) теж приймаються, але канібалізація й нові/втрачені за ними не рахуються. Для нових і втрачених потрібні два періоди.

## Кроки

1. Розрахунки скриптом:
   `python scripts/gsc_analyze.py "<current.csv>" [--previous "<prev.csv>"] --out "clients/<проєкт>/deliverables/<проєкт>_gsc_<дата>.xlsx"`
   Діапазон quick wins за замовчуванням - позиції 4-20 (змінити можна прапорцями `--pos-from/--pos-to`).
   Аркуші файлу: «Зведення», «Quick wins», «Канібалізація», «Нові», «Втрачені», «Топ сторінок», «Топ запитів».
2. Інтерпретація (твоя робота поверх цифр):
   - по топ-20 quick wins заповни колонку «Дія» - конкретно: «підсилити Title під запит Х (скіл meta-writer)», «додати блок про Y на сторінку», «поставити 3-5 внутрішніх посилань (internal-linking)»;
   - по канібалізації визнач канонічний URL для кожного запиту (колонка «Канонічний URL»), для решти - що робити (переоптимізація, canonical, 301, об'єднання);
   - по втрачених - згрупуй причини-гіпотези.
3. Резюме тімліду: топ-5 дій з очікуваним ефектом.

## Правила

- Причини падінь не вигадуються: гіпотеза позначається як гіпотеза + написано, чим її перевірити (звірити дати з апдейтами Google, подивитися сторінку, краул).
- Не пропонувати дію «писати більше контенту» без прив'язки до конкретного запиту й сторінки.

## Чек-лист перед здачею

- [ ] Гіпотези позначені як гіпотези

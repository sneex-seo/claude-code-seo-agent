# Метатеги

Вхід: пари URL + головний ключ (зазвичай із кластеризації: колонки URL + Group) або список від тімліда. Пакет - нормальний режим, один URL - окремий випадок.

## Дані до генерації (обов'язково)

1. **Сторінка**: WebFetch кожного URL - поточні Title / Description / H1, суть сторінки, точне написання бренду (регістр!).
2. **SERP**: `python scripts/serpstat_api.py top "<ключ>"` - топ-10 URL (безкоштовно, без тайтлів). Тайтли конкурентів: WebFetch 2-3 верхніх URL (не маркетплейсів) або `python scripts/dataforseo_api.py serp "<ключ>"` - одразу дає тайтли (~$0.002 за ключ, баланс берегти).
3. З тайтлів конкурентів випиши: часті слова й біграми, кандидатів на другу ключову фразу.

Без огляду сторінки й топу мета не пишуться.

## Правила

- **Title**: основний ключ ближче до початку + одна вторинна фраза (з кластера або кандидатів із SERP); бренд у кінці через « - Бренд» або « | Бренд», регістр бренду - як на сайті; довжина 45-65 символів (до 70 допустимо); без переспаму й КАПСУ.
- **Description**: 140-165 символів; ключ у перших 120; конкретна вигода + заклик до дії; без порожніх обіцянок.
- **H1**: з ключем, без брендового хвоста, не дублює Title дослівно.
- Комерційний інтент → комерційне слово (купити / замовити / ціна / доставка) у Title або Description.
- Емодзі - лише якщо їх явно дозволено в PROJECT.md проєкту. За замовчуванням - ні.
- Мова - за ключем (правило CLAUDE.md), не змішувати.
- Title всередині пакета не дублюються; від конкурентів відрізняються (не копіювати топ-1).
- Ліміти довжин - предмет уточнення з тімлідом на першому прийманні; після уточнення зафіксуй в «Уроках приймань».

## Результат

`clients/<проєкт>/deliverables/<проєкт>_meta_<YYYY-MM-DD>.xlsx`, писати скриптом:

1. **Мета**: URL | Ключ | Title | len(T) | Description | len(D) | H1 | Поточний Title | Коментар
2. **Зведення**: скільки сторінок, які URL конкурентів переглядав, дата, джерело SERP

Колонки len рахуються програмно під час запису файлу, не на око. Оформлення: шапка жирним, автофільтр, закріплений перший рядок; поточний і новий Title стоять поруч, щоб тімлід бачив «було / стало» і довжину.

На запит тімліда: JSON-LD розмітка (Product / FAQPage / BreadcrumbList) окремою колонкою або файлом - генеруй за реальними даними сторінки, нічого не вигадуючи (ціни, рейтинги - лише якщо вони є на сторінці).

## Чек-лист перед здачею

- [ ] Довжини пораховані скриптом і в межах
- [ ] Ключ на початку Title, бренд у кінці, регістр правильний
- [ ] Комерційні слова там, де комерційний інтент
- [ ] Мова = мова ключа, без змішування
- [ ] Немає дублів Title у пакеті
- [ ] Сторінки й топ справді переглядав (список URL - у «Зведенні»)

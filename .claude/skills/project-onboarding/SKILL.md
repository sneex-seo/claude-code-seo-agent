# Онбординг SEO-проєкту

Мета: за один прогін створити робочий контекст проєкту в `clients/<slug>/`, щоб далі будь-яке завдання виконувалося «в контексті клієнта», а не з нуля. `<slug>` - коротка латинська назва за доменом (shop.com.ua → shop).

## Крок 1. Питання тімліду

Спитай те, чого не знаєш (не вигадуй):

1. Домен і тип бізнесу (магазин / послуги / контент / SaaS)
2. Регіони та мови просування
3. CMS і які є доступи (CMS, GSC, аналітика)
4. План робіт (xlsx) - чи є, де лежить
5. Відомі конкуренти (на думку клієнта / тімліда)
6. Обмеження ніші (18+, YMYL, юридичні заборони, правила бренду)

Якщо тімлід дав лише домен - постав питання одним списком і продовжуй з тим, що відомо; те, на що не відповіли, фіксуй у «Відкритих питаннях» паспорта.

## Крок 2. Огляд сайту (самостійно)

- WebFetch: головна + 2-3 ключові категорії / сторінки послуг.
- Зафіксуй: тип сайту, основні розділи, поточні Title / Description / H1 переглянутих сторінок, CMS за маркерами коду (`generator`, шляхи `/wp-content/`, `/bitrix/`, характерні шаблони платформ), мовні версії та їхню схему URL.

## Крок 3. Baseline за даними (не з голови)

Ринок UA:

- `python scripts/serpstat_api.py domain <домен>` - видимість, кількість ключів, оцінка трафіку
- `python scripts/serpstat_api.py domain-keywords <домен> --out "clients/<slug>/baseline/serpstat_keywords_<YYYY-MM-DD>.csv"` - топ-ключі домену з позиціями

Поза UA і для точкових перевірок SERP: `python scripts/dataforseo_api.py ...`

Конкуренти: якщо тімлід не назвав - візьми перетин за ключами (Serpstat) і перевір очима, що це справжні конкуренти, а не маркетплейси чи агрегатори.

Є вивантаження GSC в `inbox/` → зведи топ-сторінки й топ-запити в baseline. Даних немає взагалі (молодий домен) → так і запиши: «baseline порожній, <дата>».

## Крок 4. Створи структуру

```
clients/<slug>/
├── PROJECT.md      ← за шаблоном нижче
├── lessons.md      ← "# Уроки проєкту <домен>" + порожній список
├── inbox/          ← вхідні вивантаження від тімліда
├── baseline/       ← дані замірів з датами в назвах
├── semantics/      ← ядра й кластеризації
└── deliverables/   ← результати для тімліда
```

## Шаблон PROJECT.md

```markdown
# <домен> - паспорт проєкту
Оновлено: <YYYY-MM-DD>

## Бізнес
Ніша, модель, регіони, мови, ЦА, сезонність.

## Технічно
CMS: ... | Доступи: CMS ?, GSC ?, аналітика ? | Особливості (фільтри, піддомени, мовні версії).

## Конкуренти
| Домен | Джерело (Serpstat / тімлід) | Коментар |
|---|---|---|

## Baseline <YYYY-MM-DD>
Видимість, оцінка трафіку, топ-10 ключів, сильні розділи. Файли: baseline/...

## План робіт
Шлях до xlsx / «немає - працюємо за запитами».

## Обмеження
...

## Відкриті питання
- [ ] ...

## Історія рішень
| Дата | Рішення | Чому |
|---|---|---|
```

## Чек-лист перед здачею

- [ ] У кожної цифри baseline є джерело й дата
- [ ] Конкуренти перевірені очима (не маркетплейси, якщо ніша не про них)
- [ ] Питання без відповіді - у «Відкритих питаннях», а не вигадані
- [ ] Резюме тімліду: що зібрано, яких доступів бракує і що вони дадуть (GSC - пріоритет №1)

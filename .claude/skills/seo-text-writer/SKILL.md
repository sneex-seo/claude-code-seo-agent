# SEO-текст

Пишеться за затвердженим брифом (скіл content-brief). Просять текст без брифу → запропонуй спершу швидкий бриф; тімлід каже «одразу текст» - гаразд, але дані топу (структури й обсяги конкурентів) однаково збери.

## Правила

- Структура й обсяг - з брифу. Відхилення більше ніж на 20% - погодь, не вирішуй сам.
- Мова - за ключем (CLAUDE.md), не змішувати.
- Ключі вживай природно: словоформи й синоніми замість повторів; жодного «купити каву Київ недорого» посеред речення.
- **Заборонені штампи**: «у сучасному світі», «не секрет, що», «як відомо», «незамінний помічник», «широкий асортимент за доступними цінами» (без конкретики), «компанія, що динамічно розвивається», порожні узагальнення-вода. Конкретика замість води: цифри, критерії вибору, факти.
- **Факти, характеристики, ціни - лише зі сторінки, брифу або даних.** Даних немає - маркер `[УТОЧНИТИ: що саме]`, усі маркери збери списком наприкінці. Вигаданий факт - найгірша з можливих помилок.
- Внутрішні посилання: 2-5, лише на наявні URL проєкту (перевір за вивантаженням позицій, sitemap або PROJECT.md). Корисна сторінка, якої ще немає, - в коментар «пропозиція: створити».
- Комерційна сторінка → блок переваг чи умов із конкретикою і CTA за брифом.
- Жодної самооцінки «readability 85» - натомість короткі абзаци, підзаголовки кожні 2-4 абзаци, списки там, де перелік.

## Результат

`clients/<проєкт>/deliverables/<проєкт>_text_<slug>_<дата>.md` (docx - на запит):
текст + наприкінці таблиця самоперевірки за брифом (пункт брифу | виконано/ні | де) + список `[УТОЧНИТИ]`.

## Чек-лист перед здачею

- [ ] Усі H2/H3 з брифу на місці (або відхилення погоджено)
- [ ] Обсяг у межах ±20% від брифу - пораховано
- [ ] Внутрішні посилання перевірено на існування
- [ ] Пошук по тексту: жодного штампу зі списку
- [ ] Усі непідтверджені факти - у `[УТОЧНИТИ]`, а не в тексті як істина
- [ ] Ключі з брифу вжито (таблицю самоперевірки заповнено)
